# 03 モデルの姿勢と物理調整

この章では、モデルをインポートした後に初期姿勢を確認し、髪・スカート・袖・アクセサリーなどの物理挙動を調整する方法を説明します。

## この章を使える条件

ここで説明するKawaiiPhysicsノードとコリジョンアセットは、[モデルのインポート](02-モデルのインポート.md)で **フィジックスを有効化** をオンにした場合だけ作成されます。インポート後、Content Browserでは通常、次のアセットを確認できます。

| アセット | 役割 |
| --- | --- |
| `ABP_Post_<モデル名>` | 再生中にMMDのIK、追加変形、腕の拘束補正（胴体と脚の回避を含む）、KawaiiPhysicsを動作させるポストプロセスAnimation Blueprint。 |
| `Phy/PA_<モデル名>_ALL` | 使用可能なMMDコリジョンをすべて含むPhysics Asset。KawaiiPhysicsの既定値です。 |
| `Phy/PA_<モデル名>_G00`、`_G01` … | MMDのコリジョングループごとに分けたPhysics Asset。確認や手動選択に使います。実際に作られる番号はPMXモデルによって異なります。 |
| `IKR_<モデル名>` | 現在のPMXモデル用IK Rig。PMXのリターゲットチェーン、Full Body IK Solver、手・足・つま先のGoal、PMX共有Body RootとRoot Motion Boneの設定を含みます。 |
| `RTG_<モデル名>` | UE5 Mannyのモーションを現在のMMDモデルへ変換します。 |
| `RTG_<モデル名>_ToManny` | 現在のMMDモデルのモーションをUE5 Mannyへ変換します。 |

物理アセットがない場合は、**フィジックスを有効化** をオンにしたか、KawaiiPhysicsプラグインが有効か、PMXに有効な剛体と動的ボーンチェーンがあるかを確認してください。物理を無効にしてインポート済みの場合は、PMXをもう一度、**フィジックスを有効化** をオンにしてインポートします。同名アセットがすでにある場合は、混乱を避けるため新しいコンテンツフォルダを使うのがおすすめです。

## ABPの役割

`ABP_Post_<モデル名>`はモデルのポストプロセスAnimation Blueprintです。VMDやSequencerの基本モーションを置き換えるものではなく、基本モーションの後でMMDモデル自身に必要なIK、追加変形、腕の拘束補正（胴体と脚の回避を含む）、物理を続けて適用します。

**腕の拘束補正** は、上腕・前腕・手が胴体、首、頭部、脚、反対側の腕へ入り込むのを抑えるための機能です。この章では用途だけ知っておけば十分で、通常は自動生成された初期値のままで構いません。キャラクターモーションを導入したあと、[05-2 腕の拘束補正](05-2-腕の拘束補正.md) で Debug Draw、判定範囲、詳しい調整方法を説明します。

VMD、Control Rig、その他のSequencerアニメーションがポーズの主な入力です。プレビューや再生中は、髪やスカートなどの動的ボーンが現在のポーズとモデルの移動に応じて再計算されます。

**フィジックスを有効化** をオフにした場合でも、MMD IK、追加変形、腕の拘束補正用の`ABP_Post`が作成されることはあります。しかし、この章で調整するKawaiiPhysicsノードとコリジョングループ別Physics Assetは作成されません。

## ABP内のIKノードの役割

ABP内のMMD IK/制約ノードは、PMXモデル自身に保存されている設定に従い、足・膝・腕などをモデル作者が意図した関係に保ちます。また、MMDの追加回転や追加移動も処理します。

自動化された設定により、通常はMMDのように各IKチャンネルを個別に調整する必要はありません。ただし、生成されたノードに表示される対応IK値は、MMDの各IKチャンネルのオン・オフに相当します。

ほとんどの場合、生成されたIKノードはそのまま使用してください。モデルごとにボーンや制約が異なるため、手動変更すると膝が逆に曲がる、足がずれる、腕が反転する、MMDと動きが合わないなどの問題が起きることがあります。髪・スカート・袖など動的ボーンのコリジョンは通常、Physics AssetとKawaiiPhysicsで調整します。**腕や手がキャラクター自身の胴体、頭部、脚、反対側の腕へ入り込む場合**は、[05-2 腕の拘束補正](05-2-腕の拘束補正.md)を使用します。

## IKRとRTGの関係

`IKR_<モデル名>`（IK Rig）は現在のPMXモデルの「骨格ルール」です。リターゲットチェーン、IK Solver、手・足・つま先などのGoalを持ち、PMXボーンのセマンティクス、左右、役割をもとに生成されます。通常はIKRを手動編集する必要はなく、リターゲットのためにモデルのSkeletonが書き換えられることもありません。

`RTG_<モデル名>` と `RTG_<モデル名>_ToManny`（IK Retargeter）はモーション変換アセットです。それぞれ **UE5 Manny → MMD** と **MMD → UE5 Manny** に固定され、Source、Target、プレビューMesh、チェーン対応、Operation Stackを個別に持ちます。1つのRTG内でSource、Target、プレビューMeshを交換して逆方向にしないでください。逆方向では `_ToManny` アセットを使います。

現在の配布パッケージには、双方向リターゲットに必要な最小構成のUE5 Mannyアセットが同梱されています。そのため、通常は **IKアセットを作成** を有効にすればPMX IKRと2方向のRTGが生成され、プロジェクト側でMannyアセットを用意する必要はありません。プラグイン内蔵アセットが欠損または破損している場合だけRTG生成に失敗する可能性があり、その場合はインポートまたは再インポート時に警告が表示されます。

`IKR_`、`RTG_`、`ABP_Post_`の役割も異なります。IKRはリターゲット規則、RTGは別のSkeletonへのモーション変換、`ABP_Post_`は再生中のPMX Grant、CCD IK、IK Link Limit、腕の拘束補正、物理の評価を担当します。RTGで変換したモーションも、完全なMMDポーズにするにはポストプロセスAnimation Blueprintを通ります。

## RTGのOperation Stack

RTGの **Operation Stack** にある項目は上から順番に評価されます。インポート時と再構築時にプラグインが自動設定するため、通常は項目の追加・削除・ドラッグは不要です。正方向と逆方向ではリストが意図的に異なるため、一方のリストをそのままもう一方へコピーしないでください。

### 正方向：`RTG_<モデル名>`（Manny → MMD）

添付画像に示されている主な方向です。PMXの必要な構造を認識できるモデルでは、論理的な順番は次のとおりです。

| Operation | 役割 | 既定状態と推奨 |
| --- | --- | --- |
| **Pelvis Motion** | Mannyの骨盤全体の動きを、脊柱と両脚につながるPMXの共有Body Rootへ渡します。脚だけの `下半身` を骨盤として扱いません。 | 有効のまま。 |
| **MMD Virtual Waist** | RTG評価中だけ存在する一時的な腰の親を上下半身の分岐の間に用意し、FK前に両分岐を正しい空間へ置きます。Skeletonにボーンを追加しません。`Pivot Offset` の既定値はゼロで、通常は調整不要です。 | 有効のまま、FK Chainsより前。 |
| **FK Chains** | IKRのチェーン対応に従ってボーン回転を伝えます。各チェーンのTranslationは既定で `None` としPMXのボーン長を保ちます。Clavicleは `OneToOne`、Armは実際の階層から `OneToOne` または `Interpolated` を自動選択します。 | 既定値のまま。 |
| **Run IK Rig** | 現在のPMX Target IKRを指定して実行します。正方向RTGでは後段の `ABP_Post_` がPMXのCCD IKを処理するため、二重IKを避ける目的で操作全体を無効にします。脚のチェックだけを外してもUEのIK Solver自体は実行されます。 | **無効のまま**。再びオンにしない。 |
| **Root Motion** | 処理済みのTarget Pelvisから全体移動を生成し、PMXのRoot Motion Bone（通常は `全ての親`）へ書き込みます。リターゲットされない補助子ボーンには移動を伝播しません。 | 有効・既定値のまま。 |
| **Remap Curves** | Source/Targetの対応に従ってアニメーションカーブを渡します。 | 既定値のまま。 |
| **MMD Auxiliary Bone Follow** | FK後、標準リターゲットチェーンに含まれないPMX補助ボーンを現在の親のローカルポーズに追従させます。すでにリターゲットで駆動された身体の主ボーンをリセットしません。 | 表示される場合は有効のまま。 |
| **MMD Anatomical Arms** | Mannyの胸、上腕、前腕、手を使い、PMXの実際の3段の腕階層に沿って両腕を再構成します。モデルの比率や捩り・補助ボーンが異なる場合も、手の間隔、手首、指分岐の連続性を保ちます。`Hand Contact Alpha` の既定値は `1.0` で、両手が近づいたときの接触補正の強さを制御します。 | 有効のまま、`MMD Authoring IK Targets`より前。 |
| **MMD Authoring IK Targets** | 現在のSource IKRと `FK Chains` の脚・つま先マッピングからPMXの足IK / つま先IKコントロールボーンのトラックを生成します。Source側の特定のボーン名には依存せず、すでにリターゲット済みのPMX変形足ボーンからIKを逆算しません。実際のPMX CCDは `ABP_Post_` が処理します。 | 有効なPMX足IKがある場合だけ表示され、**必ず最後**。 |

### 脚がほぼ伸び切ったときの膝プリベンド補助

`MMD Authoring IK Targets` の **Leg Prebend → Enable Knee Prebend** は初期状態ではオフです。通常のモーションではオフのままで構いません。リターゲット後、脚がほぼ完全に伸びた瞬間だけ膝が反転したり、曲がる向きが不安定になったりする場合に試してください。この機能は膝の曲がる向きにヒントを与えるだけで、足IKターゲットを別のモーションへ置き換えるものではありません。

古いバージョンで生成したRTGにこの項目が無い、または有効化すると膝 / 足情報が不足しているという警告が出る場合は、PMXを再インポートし、**IK Rig / IK Retargeter** だけを上書きして `IKR_` と2つの `RTG_` を再生成してください。この機能のためにSkeletal Meshを上書きする必要はありません。

### 更新後も古いリターゲットアニメーションで足滑りや足首のねじれが残る場合

現在のバージョンでは、正方向RTGの足IK / つま先IKターゲット計算が改善されています。ただし、古いバージョンですでに書き出し / ベイク済みのAnimation Sequenceは、プラグインを更新しても自動では再計算されません。接地中の足滑りや不自然な足首のねじれが残る場合は、現在の `RTG_<モデル名>` からAnimation Sequenceを書き出し / ベイクし直してから使用するか、VMDを書き出してください。

この足ターゲット修正だけなら、既存RTGは通常再生成不要です。上記の膝プリベンドも使いたく、古いRTGに必要な設定が無い場合だけIKアセットを再生成してください。

### 逆方向：`RTG_<モデル名>_ToManny`（MMD → Manny）

逆方向アセットは既定リストから別に再構築され、論理的な順番は次のとおりです。

| Operation | 役割 | 既定状態と推奨 |
| --- | --- | --- |
| **MMD Virtual Hips** | 標準の `Pelvis Motion` を置き換えます。PMXのRoot / Center / Grooveの移動と `下半身` の回転を組み合わせ、Mannyに必要な共通 `pelvis` を合成します。脊柱と両脚が正しい親空間を共有でき、実際のボーンは作成・変更しません。`Translation Offset` の既定値はゼロで、通常は調整不要です。 | 有効のまま、FK Chainsより前。 |
| **FK Chains** | PMXの回転をMannyへ対応させ、すべてのチェーンのTranslationを `None` にしてManny本来のボーン長を保ちます。Mannyにだけ存在する掌骨チェーンは構造ボーンとして扱い、PMXの指回転を二重に適用しません。 | 既定値のまま。 |
| **Manny Finger Anchor** | FK後、手のひらと指の間にある未対応の構造リンクと指の移動を再構成します。同じ長さの指チェーンでは各関節のローカル回転を1回だけ適用し、指の過剰な曲がりを防ぎます。`Max Joint Rotation Degrees` の既定値は `120°` で、通常は変更不要です。 | 有効のまま、`MMD Spine Space`より前。 |
| **MMD Spine Space** | 逆方向FK後、Mannyの脊柱が使う上半身空間をPMXの独立した上半身分岐に合わせます。脊柱分岐だけを調整し、脚分岐まで一緒に回転させません。 | 有効のまま、Run IK Rigより前。 |
| **Run IK Rig** | MannyのTarget IKRを指定して実行します。逆方向ではTarget SkeletonのIKに必要です。逆方向FKと競合しないよう、生成設定では左右の腕IKチェーンを無効にし、脚IKは利用できる状態にします。 | **有効のまま**。 |
| **Root Motion** | `MMD Virtual Hips` で処理済みのManny Target Pelvisから全体移動を生成し、Mannyの `root` に書き込みます。リターゲットされない子ボーンには伝播しません。 | 有効・既定値のまま。 |
| **Remap Curves** | 逆方向の対応に従ってアニメーションカーブを渡します。 | 既定値のまま。 |

逆方向のリストには、PMXをTargetにした場合だけ必要な `MMD Virtual Waist`、`MMD Auxiliary Bone Follow`、`MMD Authoring IK Targets` はありません。正方向では、この操作はVMDへ再出力できるMMD作者用コントロールデータを生成し、Post Process後の最終脚ポーズそのものは生成しません。したがって、画像の **Run IK Rigが無効** という状態は正方向Manny → MMDでは正しく、`_ToManny` では生成されたRun IK Rigを有効にします。独自のリターゲットパイプラインを作る場合を除き、これらの有効状態や順番を変更しないでください。

## KawaiiPhysicsで物理を改善する

### 1. まず既定の結果を確認する

`ABP_Post_<モデル名>`を開いて **AnimGraph** に切り替えます。物理を有効にしてインポートすると、通常は `PMX Kawaii Physics (MMD2Unreal Generated)` と表示された領域にKawaiiPhysicsノードがあります。

モデルを含むLevel Sequenceを開き、短い範囲を再生します。髪が頭や肩を通り抜けないか、スカートが脚を通り抜けないか、袖やアクセサリーが揺れすぎないか、モデルの急な移動時に動的ボーンが伸びたり破綻したりしないかを確認します。

規則的な複数チェーンのスカートでは、PMXのチェーン間接続をできるだけ保持し、構造を安全に判断できる場合は不足している横方向接続も自動で補います。これらは自動生成された物理構造の一部なので、通常の調整では手作業で削除・再作成する必要はありません。スカートの各パネルが完全に別々の帯のように動く場合は、手動で制約を作る前に再インポートまたは元PMXのJoint構造を確認してください。

問題がコリジョン由来か物理パラメータ由来かを切り分け、毎回小さな変更を1つだけ行って再生してください。

### 2. KawaiiPhysicsノードでMMDコリジョングループを選ぶ

![KawaiiPhysicsノード](../DocPic/Abp_View.jpg)

MMDのコリジョングループを選択する場所は次のとおりです。

1. `ABP_Post_<モデル名>`を開き、**AnimGraph** に切り替えます。
2. 調整したいKawaiiPhysicsノードを選択します。
3. 右側の **Details** パネルで **Limits** を展開します。
4. **Physics Asset** に `PA_<モデル名>_ALL` または `PA_<モデル名>_Gxx` を指定します。
5. ABPを **Compile** して保存し、Level Sequenceをもう一度再生します。

`Gxx`の`xx`はPMX剛体のMMDコリジョングループ番号で、`00`から`15`までです。

| MMDグループ | 対応アセット |
| --- | --- |
| グループ0 | `PA_<モデル名>_G00` |
| グループ1 | `PA_<モデル名>_G01` |
| グループ2 | `PA_<モデル名>_G02` |
| … | … |
| グループ15 | `PA_<モデル名>_G15` |

![コリジョン](../DocPic/collision_change.jpg)
通常は`_ALL`を使います。すべての有効なMMDコリジョンを含み、PMXの相互非衝突マスクもPhysics Assetに反映されています。特定グループだけを確認したい、グループを比較したい、または関係のないコリジョンが動的チェーンに影響している場合だけ、対応する`_Gxx`へ切り替えます。

この項目はコリジョンの供給元を選ぶもので、どの髪やスカートのチェーンをシミュレーションするかを選ぶものではありません。シミュレーション対象はKawaiiPhysicsノードの`Root Bone`と`Additional Root Bones`で決まります。ABPに複数のKawaiiPhysicsノードがある場合は、必要に応じてノードごとに別のPhysics Assetを指定できます。

### 3. コリジョン形状を確認・調整する

`PA_<モデル名>_ALL`または`_Gxx`をダブルクリックしてPhysics Asset Editorを開きます。

1. プレビュー対象が現在のMMDモデルであることを確認します。
2. コリジョン表示を有効にし、体・頭・肩・脚の球、カプセル、ボックスが正しい位置にあるか確認します。
3. コリジョンが全体的にずれている場合は、まずモデルのインポート、骨格の姿勢、スケールを確認します。全体のずれをKawaiiPhysicsの`Radius`だけで補正しないでください。
4. 必要なら該当Bodyの位置、回転、サイズを調整してPhysics Assetを保存します。
5. ABPとLevel Sequenceに戻り、もう一度再生します。1回に1つの領域だけを変更してください。

MMDの衝突剛体はPhysics Assetの形状としてインポートされます。`_ALL`と`_Gxx`は同じPMXから生成される別のコリジョンアセットです。モデルを再インポートすると再生成される場合があるため、大きな調整は記録しておきます。

### 4. KawaiiPhysicsの基本パラメータを調整する

KawaiiPhysicsノードのDetailsで **Physics Settings** を展開します。

| パラメータ | 調整の方向 |
| --- | --- |
| `Damping` | 小さいほど揺れやすく、大きいほど鈍く重くなります。揺れが長く続くときは上げ、髪がほとんど動かないときは下げます。 |
| `Stiffness` | 大きいほど元のアニメーション姿勢へ強く戻り、小さいほど自由に揺れます。スカートが飛びすぎるときは上げ、柔らかな揺れにしたいときは下げます。 |
| `Radius` / `Collision Radius` | 各動的ボーンが持つ衝突用の球半径です。大きすぎると破綻や過剰な押し出し、小さすぎると貫通が起きます。 |
| `Limit Angle` | 1ステップの物理回転を制限し、反転や振動を抑えます。`0`は無制限です。 |
| `World Damping Location`、`World Damping Rotation` | モデル全体の移動・回転が揺れへ伝わる量を調整します。急な移動で揺れすぎる場合は上げ、強い遅れを出したい場合は下げます。 |

髪として認識された動的ボーンチェーンは、通常の角度制限で髪の動きが止まらないよう、インポート時に **Limit Angle = 0**（無制限）で生成されます。スカート、袖、アクセサリーなど髪として認識されないチェーンは、通常の角度制限を使用します。

毎回1つのパラメータを少しだけ変更して再生します。ボーン長、剛体サイズ、モーションの振幅はモデルごとに違うため、別モデルの値をそのまま流用しないでください。

### 5. スカートの貫通を調整する順番

スカートの貫通は、コリジョンが小さい、グループが違う、動的ボーンの間隔が大きい、のいずれかで起きることが多いです。

1. まず`PA_<モデル名>_ALL`を選び、スカートチェーンが胴体と脚のコリジョンを認識できるか確認します。
2. Physics Asset Editorで脚、腰、胴体のコリジョンを少しだけ大きくします。メッシュの外側へ大きくはみ出させないでください。
3. KawaiiPhysicsの`Radius`を少しだけ大きくします。
4. 隣接するスカートボーンの間に隙間がある場合は、**Bones → Bone Subdivision → Bone Subdivision Count** を増やし、長いボーン区間の衝突検出密度を上げます。計算量は増えます。
5. まだ貫通する場合は、別の`Gxx`を使うべきチェーンか、PMXの非衝突マスクでその組み合わせが無効になっていないかを確認します。

逆にスカートが胴体から大きく弾かれる場合は、まず`Radius`またはコリジョン形状を小さくし、選んだグループに不要な胴体コリジョンが多く含まれていないか確認します。

## 直接変更しない方がよいもの

- 貫通を直すためにMMD IK/制約ノードを削除・並べ替えしないでください。
- 同じコリジョンをPhysics AssetとKawaiiPhysicsノードの`Spherical Limits`、`Capsule Limits`、`Box Limits`の両方へ追加しないでください。二重衝突の原因になります。
- 複数チェーン、複数Physics Asset、複数パラメータを同時に変更しないでください。
- 再インポート後は、各KawaiiPhysicsノードが意図した`_ALL`または`_Gxx`を参照しているか確認してください。

コリジョン形状、各パラメータ、ボーン細分、カーブ、外力などの詳しい内容は、[KawaiiPhysics公式コリジョン設定ガイド](https://pafuhana1213.github.io/KawaiiPhysics-Portal/en/docs/features/collision-setup)と[公式パラメータリファレンス](https://pafuhana1213.github.io/KawaiiPhysics-Portal/en/docs/parameters/physics)を参照してください。

モデルの姿勢と物理を確認できたら、次の[04 M2Uマテリアル調整](04-M2Uマテリアル調整.md)へ進みます。
