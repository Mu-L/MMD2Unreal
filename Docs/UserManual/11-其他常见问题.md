# 11 其他常见问题

这里保留无法归入某个具体操作章节的通用问题。模型、动作、镜头和导出问题请优先回到对应章节的“常见问题”部分。

## 项目文件更新

### 模型或动作的源文件更新后，为什么已有内容没有自动刷新

源文件变化不会自动改动 Unreal 里的已有资产。PMX 模型现在可以在同名冲突提示中手动选择 **重新导入PMX模型** 来更新现有模型；VMD 动作与镜头仍建议重新导入一份新的。为了避免误覆盖已经调好的内容，重要资产仍建议先备份，或先在新的内容浏览器文件夹里检查新版结果。

### 重新导入前，怎样保留自己已经调好的内容

先保存项目，并记下自己修改过的资产和位置，例如材质实例、Level Sequence、Control Rig 关键帧、Physics Asset 或 `ABP_Post_`。对于 PMX，可以先把新版导入到新的文件夹进行检查；确认模型、骨骼、材质槽和表情都符合预期后，再决定是否回到原目录使用 **重新导入PMX模型**。

不要把“重新导入”当成无条件保留所有手工调整的操作。由插件自动生成的资产可能会随导入结果更新；对于花了较多时间调节的内容，保留一份可回退的副本会更安心。新 PMX 删除掉的旧材质、贴图或其他附属资产目前不会自动从 Unreal 中清理。

## 问题不属于任何一章时，怎样开始排查

1. 先确认正在使用本手册对应的 Unreal Engine 版本，并且 `MMD2Unreal` 与 KawaiiPhysics 都已在 **编辑 > 插件** 中启用；启用后需要重启编辑器。
2. 把问题缩小到一个模型、一条动作或一个镜头，避免同时改动多个资产。
3. 查看 Unreal 的 **Output Log**，优先记录出现问题时的警告或报错，而不是只记录最终画面。
4. 如果同名资产或旧资产可能造成干扰，换一个新的内容浏览器文件夹重新导入，再比较结果。

## 寻求帮助时，准备哪些信息

提供的信息越完整，越容易复现和判断问题。建议附上：

- Unreal Engine、MMD2Unreal 与 KawaiiPhysics 的版本；
- 从导入到出现问题的最短操作步骤；
- 相关的 Output Log 警告或错误文本；
- 能说明问题的截图、短视频，或可公开的最小 PMX/VMD 示例；
- 已经尝试过的处理方式。

请避免直接发送包含私人路径、账号信息或无关项目内容的完整日志。只截取与问题发生时间相邻的部分即可。

## 先用 AI 工具主动学习和整理问题

现在的 AI 工具已经很适合帮助你理解 UE、阅读日志、整理复现步骤和查找官方资料。遇到问题时，可以先尝试使用 ChatGPT、Claude、通义千问（Qwen）、DeepSeek 等聊天工具，或 Codex、Claude Code 等 Agent Harness 工具，协助你：

- 把 Output Log 中的关键信息按时间、警告和错误分类；
- 将模糊的现象整理成可执行的复现步骤；
- 查找相关的 Unreal、KawaiiPhysics 或 MMD 数据格式文档；
- 对比当前设置与教程中的预期结果，并列出已验证和仍不确定的部分。

AI 给出的建议也需要你结合项目实际情况判断；不要把未验证的操作直接批量应用到重要资产。先在副本或新文件夹中做小范围验证，再决定是否采用。

## 尽量不要模糊提问

“导入坏了”“物理不对”“模型炸了”很难让任何人准确判断。更有效的提问应说明：你想达到什么效果、实际看到了什么、从哪一步开始出现、是否能稳定复现，以及已经尝试了哪些方法。把问题缩小并提供证据，往往比一次发送大量无关文件更有帮助。

## 把 Unreal 当作继续成长的跳板

从 MMD 走到 Unreal，意味着你会接触到更多工具、概念和需要自己判断的选择。这个过程确实需要更主动地学习、排查和培养探索能力，但它也是把创作能力带到更高层次的机会。

希望大家能借助这个插件和 UE，把“解决一个问题”的经验慢慢变成自己的方法：更自由地实现想法、建立可迁移的技术能力，并在未来的创作、就业和生活中获得更多可能性。
