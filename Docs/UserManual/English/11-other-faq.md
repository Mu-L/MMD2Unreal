# 11 Other Common Problems

This chapter keeps general questions that do not belong to one specific operation. For model, motion, camera, or export problems, first return to the **Common Problems** section in the relevant chapter.

> **Note:** This manual was translated by AI from the Chinese original, which is the authoritative version. Some expressions may not be fully accurate.

## Source Files and Existing Assets

### Why do existing assets not refresh automatically when the model or motion source changes?

Changing a source file does not automatically modify assets that are already inside Unreal. PMX models can now be updated by choosing **Reimport PMX Model** in the same-name conflict warning. VMD motions and cameras should still be imported as a fresh copy. For important work, back up tuned assets first or inspect the new source in a separate Content Browser folder before replacing anything.

### How can I preserve adjustments before reimporting?

Save the project first, then note the assets and locations you changed, such as material instances, Level Sequences, Control Rig keys, Physics Assets, or `ABP_Post_`. For PMX, you can first import the new version into a separate folder and inspect its model, skeleton, material slots, and expressions. Once the result is correct, return to the original destination and decide whether to use **Reimport PMX Model**.

Do not treat reimporting as an operation that unconditionally preserves every manual adjustment. Assets generated by the plugin can change with the import result; keep a recoverable copy of work that took significant time to tune. Materials, textures, or other companion assets that no longer exist in the new PMX are not automatically removed from Unreal yet.

## How to start when a problem does not fit another chapter

1. Confirm that you are using the Unreal Engine version covered by this manual and that both `MMD2Unreal` and KawaiiPhysics are enabled under **Edit > Plugins**. Restart the editor after enabling them.
2. Reduce the issue to one model, one motion, or one camera. Avoid changing multiple assets at the same time.
3. Check Unreal's **Output Log** and record the warnings or errors that appear when the problem occurs, rather than only the final image.
4. If same-named or older assets could interfere, import again into a new Content Browser folder and compare the result.

## What to prepare when asking for help

The more complete the information, the easier it is to reproduce and diagnose a problem. Include:

- Unreal Engine, MMD2Unreal, and KawaiiPhysics versions;
- the shortest steps from import to the problem;
- the relevant Output Log warning or error text;
- a screenshot, short video, or a shareable minimal PMX/VMD example; and
- the fixes you have already tried.

Avoid sending complete logs that contain private paths, account information, or unrelated project data. Extract only the part close to when the issue occurred.

## Learn and organise the problem with AI tools first

Today's AI tools are well suited to understanding Unreal, reading logs, organising reproduction steps, and finding official information. When you encounter a problem, try chat tools such as ChatGPT, Claude, Qwen, or DeepSeek, or agent-harness tools such as Codex and Claude Code, to help you:

- classify key Output Log information by time, warnings, and errors;
- turn a vague symptom into reproducible steps;
- find relevant Unreal, KawaiiPhysics, or MMD data-format documentation; and
- compare the current setup with the expected result in a tutorial, separating verified facts from open questions.

You still need to judge AI suggestions against your actual project. Do not apply unverified changes in bulk to important assets. Test a small scope in a copy or new folder before deciding whether to adopt a change.

## Avoid vague questions

“The import is broken”, “the physics is wrong”, or “the model exploded” is difficult for anyone to diagnose accurately. A useful question states the desired result, what you actually saw, when it began, whether it is repeatable, and what you have already tried. Narrowing the problem and providing evidence is usually more useful than sending a large number of unrelated files.

## Treat Unreal as a stepping stone for further growth

Moving from MMD to Unreal means encountering more tools, concepts, and decisions that you need to make yourself. It takes more active learning, debugging, and exploration, but it is also an opportunity to take your creative ability further.

Use this plugin and Unreal to turn each solved problem into your own method: realise ideas more freely, build transferable technical skills, and create more possibilities for your future creative work, career, and life.
