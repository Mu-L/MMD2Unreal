# 03 模型姿态与物理调优

本章介绍模型导入后的两个检查点：先确认模型的初始姿态，再检查头发、裙摆、袖子等部位的物理效果。

## 本章的适用条件

本章中的 KawaiiPhysics 节点和碰撞资产，只有在[导入模型](02-导入模型.md)时勾选 **启用物理** 后才会生成。导入完成后，通常可以在 Content Browser 中找到：

| 资产 | 作用 |
| --- | --- |
| `ABP_Post_<模型名>` | 后处理 Animation Blueprint（动画蓝图），让 MMD 的 IK、追加变形、手臂约束修正（包括身体与腿部避让）和 KawaiiPhysics 物理在播放时正常工作。 |
| `Phy/PA_<模型名>_ALL` | 包含模型全部可用 MMD 碰撞体的 Physics Asset，KawaiiPhysics 默认使用它。 |
| `Phy/PA_<模型名>_G00`、`_G01` … | 按 MMD 碰撞组拆分的 Physics Asset，用于检查或手动选择特定碰撞组。实际生成哪些编号取决于 PMX 模型。 |
| `IKR_<模型名>` | 当前 PMX 模型的 IK Rig，包含按 PMX 骨骼生成的重定向链、Full Body IK 解算器、手/足/趾 Goal，以及 PMX 共享身体根和 Root Motion Bone 设置。 |
| `RTG_<模型名>` | 把 UE5 Manny 的动作转换到当前 MMD 模型。 |
| `RTG_<模型名>_ToManny` | 把当前 MMD 模型的动作转换到 UE5 Manny。 |

如果这些物理资产不存在，请检查：

1. 导入模型时是否勾选了 **启用物理**。
2. 项目是否启用了 KawaiiPhysics 插件。
3. PMX 是否包含有效的物理刚体和动态骨骼链。

已经在未勾选物理的情况下导入模型时，建议重新导入 PMX，并勾选 **启用物理**。如果项目中已有同名资产，可先导入到新的内容目录，避免把正在使用的资产混淆。

## ABP 的作用

`ABP_Post_<模型名>` 是模型的后处理动画蓝图。它不会替代 VMD 或 Sequencer 中的基础动画，而是在基础动画之后继续处理 MMD 模型本身需要的 IK、追加变形、手臂约束修正（包括身体与腿部避让）和物理效果。

其中 **手臂约束修正** 用于减少上臂、前臂和手掌穿进躯干、颈部、头部、腿部，或左右手臂互相穿透。这里先知道它的用途即可，通常保持自动生成的默认设置；等角色动作导入后，再按 [05-2 手臂约束修正](05-2-手臂约束修正.md) 查看 Debug Draw、碰撞范围和详细调节方法。

因此，Sequencer 中的 VMD、Control Rig 和其他动画仍然是姿态的主要来源；播放或预览时，头发、裙摆等动态骨骼会根据当前姿态和模型移动重新计算。

导入时不勾选 **启用物理**，插件仍可能创建用于 MMD IK/追加变形与手臂约束修正的 `ABP_Post`，但不会创建本章所需的 KawaiiPhysics 节点和按碰撞组生成的物理资产。因此，这种情况下不能通过本章的方法调节 MMD 物理。

## ABP 中 IK 节点的功能

ABP 中的 MMD IK/约束节点会按照 PMX 模型自身的设置，让脚部、膝盖、手臂等部位保持模型作者预期的关系，并处理 MMD 的追加旋转或追加位移。

引入自动化算法后，大多数情况下不需要像 MMD 那样单独调节每个 IK 通道是否开启，但还是需要说明：**IK 节点上的对应 IK 数值就是对应 MMD 中 IK 通道的开关。**

绝大部分情况下不需要改动 ABP 内的 IK 节点。不同模型的骨骼和约束可能不同，手动修改很容易造成膝盖反向、脚部漂移、手臂翻转或动作与 MMD 不一致。头发、裙摆、袖子等动态骨骼的碰撞问题通常应通过 Physics Asset 和 KawaiiPhysics 参数解决；如果是**手臂或手掌穿进角色自身身体、头部、腿部或另一侧手臂**，则使用 [05-2 手臂约束修正](05-2-手臂约束修正.md)。

## IKR 与 RTG 的关系

`IKR_<模型名>`（IK Rig）是当前 PMX 模型的“骨架规则”：它记录重定向链、IK 解算器以及手、脚、趾等 Goal。导入器会根据 PMX 骨骼的语义、左右侧和用途生成这些内容；正常使用时不需要手动改动 IKR，也不会为了重定向去改写模型的 Skeleton。

`RTG_<模型名>` 和 `RTG_<模型名>_ToManny`（IK Retargeter）则是“动作转换器”。它们分别固定为 **UE5 Manny → MMD** 和 **MMD → UE5 Manny**，每个资产都有自己独立的 Source、Target、预览模型、链映射和操作堆栈。不要在同一个 RTG 里手动交换 Source、Target 或预览模型来反转方向；反向转换请直接使用 `_ToManny` 资产。

当前发布包已经内置双向重定向所需的精简 UE5 Manny 资源，因此正常情况下勾选 **创建IK资产** 后会同时生成 PMX IKR 和两个方向的 RTG，不需要项目另外提供 Manny。只有插件内置资源缺失或损坏时，相关 RTG 才可能无法生成，并会在导入或重新导入时给出提示。

`IKR_`、`RTG_` 与 `ABP_Post_` 的职责也不同：IKR 用于重定向规则，RTG 用于把动作转换到另一套骨架，`ABP_Post_` 则在播放时继续执行 PMX 的 Grant、CCD IK、IK Link Limit、手臂约束修正和物理。即使使用 RTG 得到了动作，完整的 MMD 姿态仍由后处理动画蓝图完成。

## RTG 的操作堆栈

打开 RTG 后，在 **操作堆栈（Operation Stack）** 中看到的项目是按顺序计算的。导入器会在创建或重建 RTG 时自动配置它们；普通使用不需要自行新增、删除或拖动项目。正向和反向的列表不同，不能把一套列表直接复制到另一套资产。

### 正向：`RTG_<模型名>`（Manny → MMD）

这就是截图所示的主要使用场景。对于能够识别出对应 PMX 结构的模型，列表逻辑顺序为：

| 操作 | 作用 | 默认状态与建议 |
| --- | --- | --- |
| **Pelvis Motion** | 把 Manny 的骨盆整体运动传给 PMX 中同时连接脊柱和双腿的共享身体根，避免把只负责腿部的 `下半身` 当成骨盆。 | 保持启用。 |
| **MMD Virtual Waist** | 在上下半身支路之间提供一个只在 RTG 求值期间存在的临时腰部父级，让两条支路在 FK 前处于正确空间；它不会向 Skeleton 添加骨骼。`Pivot Offset` 默认是零，通常不需要调整。 | 保持启用，并位于 FK Chains 之前。 |
| **FK Chains** | 按 IKR 的链映射传递骨骼旋转。默认所有链的 Translation 都是 `None`，以保留 PMX 自身的骨长；Clavicle 使用 `OneToOne`，Arm 会根据真实层级在 `OneToOne` 与 `Interpolated` 之间自动选择。 | 保持默认。 |
| **Run IK Rig** | 指定并运行当前 PMX 的 Target IKR。正向 RTG 默认关闭整个操作，因为后面的 `ABP_Post_` 会按 PMX 规则完成 CCD IK；只关闭腿部复选项并不能避免 UE 继续运行 IK Solver。 | **保持关闭**。不要重新勾选。 |
| **Root Motion** | 从已经处理过的目标骨盆生成整体位移，写入 PMX 的 Root Motion Bone（通常是 `全ての親`），并避免把位移传播给未重定向的辅助子骨。 | 保持启用和默认设置。 |
| **Remap Curves** | 按 Source/Target 的映射关系传递动画曲线。 | 保持默认。 |
| **MMD Auxiliary Bone Follow** | 在 FK 之后，让未进入标准重定向链的 PMX 辅助骨跟随当前父级的局部姿态；已经由重定向操作驱动的身体主链不会被它再次重置。 | 有该项时保持启用。 |
| **MMD Anatomical Arms** | 以 Manny 的胸部、上臂、前臂和手为输入，按 PMX 的真实三段手臂层级重建两侧手臂，并保持手掌间距、腕部位置以及手指支路的连续性；它用于修正不同模型比例和扭转/辅助骨带来的手臂偏差。`Hand Contact Alpha` 默认是 `1.0`，控制双手靠近时的接触修正强度。 | 保持启用，并位于 `MMD Authoring IK Targets` 之前。 |
| **MMD Authoring IK Targets** | 根据当前 Source IKR 与 `FK Chains` 的腿 / 脚趾映射生成 PMX 的足 IK / 足先 IK 控制骨轨道，不依赖 Source 模型的具体骨骼命名，也不会读取已经重定向后的 PMX 足骨来反推 IK。真正的 PMX CCD 仍由 `ABP_Post_` 完成。 | 有有效 PMX 足部 IK 时才会出现；**必须保持最后**。 |

### 膝盖接近伸直时的预弯辅助

`MMD Authoring IK Targets` 的 **Leg Prebend → Enable Knee Prebend** 默认关闭。普通动作保持关闭即可；如果重定向后的腿在接近完全伸直时偶尔出现膝盖反折、左右跳向或弯曲方向不稳定，可以尝试开启它。它只帮助膝盖确定弯曲方向，不会把足 IK 目标改成另一套结果。

如果 RTG 是较早版本生成的，看不到这个选项，或开启后提示缺少膝盖 / 足部信息，请在 PMX 重新导入选项中只覆盖 **IK Rig / IK Retargeter**，让插件重建 `IKR_` 和两个 `RTG_`。不需要为了这个功能覆盖骨骼网格体。

### 升级后旧的重定向动画仍然脚滑或脚踝扭转

当前版本已经改进正向 RTG 的足 IK 和足先 IK 目标。已经在旧版本中导出或烘焙成 Animation Sequence 的动作不会随插件升级自动重算。如果旧动画仍有着地脚滑或脚踝异常扭转，请从当前 `RTG_<模型名>` 重新导出 / 烘焙 Animation Sequence，再继续使用或导出 VMD。

仅为了这项足部修正，现有 RTG 通常不需要重建；只有要使用上面的膝盖预弯，而旧 RTG 缺少对应设置时，才需要重建 IK 资产。

### 反向：`RTG_<模型名>_ToManny`（MMD → Manny）

反向资产会从默认列表重新构建，逻辑顺序为：

| 操作 | 作用 | 默认状态与建议 |
| --- | --- | --- |
| **MMD Virtual Hips** | 替代原生 `Pelvis Motion`，把 PMX 的 Root / Center / Groove 位移与 `下半身` 的旋转合成为 Manny 所需的共同 `pelvis`，让脊柱和双腿共享正确的父空间；它不会创建或修改真实骨骼。`Translation Offset` 默认是零，通常不需要调整。 | 保持启用，并位于 FK Chains 之前。 |
| **FK Chains** | 将 PMX 的旋转映射到 Manny，并把所有链的 Translation 设为 `None`，保留 Manny 自身的骨长。Manny 额外的掌骨链保持为结构骨，不重复应用 PMX 手指旋转。 | 保持默认。 |
| **Manny Finger Anchor** | 在 FK 后重建手掌与手指之间未映射的结构骨和手指平移；等长手指链按每个关节的局部旋转只应用一次，避免手指过度弯曲。`Max Joint Rotation Degrees` 默认限制为 `120°`，通常不需要修改。 | 保持启用，并位于 `MMD Spine Space` 之前。 |
| **MMD Spine Space** | 在反向 FK 后校正 Manny 脊柱使用的上半身空间，使 PMX 的独立上半身支路正确接到 Manny 胸部；它只调整脊柱支路，不会把腿部支路一起旋转。 | 保持启用，并位于 Run IK Rig 之前。 |
| **Run IK Rig** | 指定并运行 Manny 的 Target IKR。反向需要开启它来完成目标骨架的 IK；为避免与反向 FK 重复，生成器会关闭其中左右手臂的 IK 链，腿部 IK 仍可使用。 | **保持开启**。 |
| **Root Motion** | 从已经由 `MMD Virtual Hips` 处理过的 Manny 目标骨盆生成整体位移，写入 Manny 的 `root`，并关闭向未重定向子骨传播。 | 保持启用和默认设置。 |
| **Remap Curves** | 按反向映射传递动画曲线。 | 保持默认。 |

反向列表中不会出现只适用于 PMX Target 的 `MMD Virtual Waist`、`MMD Auxiliary Bone Follow` 和 `MMD Authoring IK Targets`。正向 RTG 中该操作生成的是可以继续导出为 VMD 的 MMD 控制数据，而不是 Post Process 求解后的最终腿姿势。因此，截图里看到的 **Run IK Rig 关闭** 是正向 Manny → MMD 的预期状态；打开 `_ToManny` 时，反向列表中的 Run IK Rig 应为开启。除非你正在制作自定义重定向管线，否则不要改变这些操作的顺序或启用状态。

## 使用 KawaiiPhysics 改善物理效果

### 1. 先用默认配置观察问题

在 Content Browser 中找到 `ABP_Post_<模型名>`，打开它的 AnimGraph。启用物理后，图表中会有自动生成的 KawaiiPhysics 节点，通常位于带有 `PMX Kawaii Physics (MMD2Unreal Generated)` 标记的区域。

先不要修改 IK 节点。打开一个包含该模型的 Level Sequence，播放一小段动作，分别观察：

- 头发是否穿过头部或肩膀；
- 裙摆是否穿过腿部；
- 袖子、领带或配饰是否抖动过大；
- 模型快速转身或移动时，动态骨骼是否突然拉长、爆开或停滞。

对规则的多链裙摆，插件会优先保留 PMX 原有的链间连接，并在能够安全判断时补全缺失的横向连接。这些连接是自动生成物理结构的一部分，普通调优时不需要手工删除或重建；如果裙片彼此完全散开，再考虑重新导入或检查原 PMX 的 Joint 结构。

先确认问题属于“碰撞体不合适”还是“物理参数不合适”，再做一次小幅修改并重新预览。

### 2. 在 KawaiiPhysics 节点选择 MMD 碰撞组
![KawaiiPhysics 节点](DocPic/Abp_View.jpg)

这是选择对应 MMD 碰撞组的入口：

1. 打开 `ABP_Post_<模型名>`，切换到 **AnimGraph**。
2. 单击要调节的 KawaiiPhysics 节点。
3. 在右侧 **Details** 面板展开 **Limits**。
4. 在 **Physics Asset** 属性中选择 `PA_<模型名>_ALL` 或 `PA_<模型名>_Gxx`。
5. 点击工具栏 **Compile**，保存 ABP，再回到 Level Sequence 预览。

`Gxx` 中的 `xx` 就是 PMX 刚体的 MMD 碰撞组编号，编号范围为 `00` 到 `15`。例如：

| MMD 碰撞组 | 对应资产 |
| --- | --- |
| 组 0 | `PA_<模型名>_G00` |
| 组 1 | `PA_<模型名>_G01` |
| 组 2 | `PA_<模型名>_G02` |
| … | … |
| 组 15 | `PA_<模型名>_G15` |

![碰撞组选择](DocPic/collision_change.jpg)
默认建议使用 `_ALL`。它包含所有有效的 MMD 碰撞体，并且导入器已经把 PMX 的双向不碰撞遮罩写入 Physics Asset。只有在需要隔离某个碰撞组、比较不同组的效果，或模型的某条动态链明显被不相关碰撞体干扰时，才将 KawaiiPhysics 节点的 **Physics Asset** 换成对应的 `_Gxx` 资产。

这里选择的是“碰撞体的来源”，不是选择哪一条头发或裙摆骨骼进行模拟。模拟骨骼仍由该 KawaiiPhysics 节点的 `Root Bone` 和 `Additional Root Bones` 决定。一个 ABP 可能有多个 KawaiiPhysics 节点；需要单独处理时，可以分别为节点指定碰撞资产。

### 3. 检查和调整碰撞形状

双击 `PA_<模型名>_ALL` 或某个 `_Gxx` 资产，打开 Physics Asset Editor：

1. 确认预览网格是当前 MMD 模型。
2. 打开碰撞显示，检查身体、头部、肩膀和腿部的球体、胶囊体或盒体是否位于正确位置。
3. 如果碰撞体明显偏离模型，优先检查模型导入、骨骼姿态和缩放；不要先通过放大 KawaiiPhysics 的 `Radius` 来补偿整体偏移。
4. 需要修正形状时，调整对应 Body 的位置、旋转或尺寸，然后保存 Physics Asset。
5. 回到 ABP 和 Level Sequence 播放验证。只改动一个区域，便于判断是哪项设置产生了效果。

MMD 的碰撞刚体会被导入为 Physics Asset 中的碰撞形状。`_ALL` 和 `_Gxx` 是由同一 PMX 数据生成的不同碰撞资产；重新导入模型时，相关生成资产可能会重新生成，因此建议把自定义调节记录下来。

### 4. 调整 KawaiiPhysics 的基础参数

仍然在 KawaiiPhysics 节点的 Details 面板中，展开 **Physics Settings**：

| 参数 | 调整方向 |
| --- | --- |
| `Damping` | 越小越容易摆动，越大越快变得迟钝、沉重。头发完全不动时可适当减小；抖动持续太久时可适当增大。 |
| `Stiffness` | 越大越倾向于回到动画原姿态，越小越自由。裙摆被动作甩飞时通常应适当增加；想要更柔软的摆动时可适当降低。 |
| `Radius` / `Collision Radius` | 动态骨骼自身用于推开碰撞体的半径。过大容易造成爆开或相互挤压，过小则容易穿透。 |
| `Limit Angle` | 限制单步物理旋转幅度，可抑制突然翻转和抖动。`0` 表示不限制；出现异常旋转时可设置一个合理的正值。 |
| `World Damping Location`、`World Damping Rotation` | 控制模型整体移动、旋转对摆动的传递。模型快速移动时动态骨骼甩动过强，可适当提高；希望有明显拖尾时再降低。 |

导入器会把识别为头发的动态骨骼链自动设为 **Limit Angle = 0**（无限制），避免头发被普通角度上限卡住。裙摆、袖子、饰品等未识别为头发的链仍按普通角度限制生成。

建议每次只调整一个参数，并以小幅度反复预览。不同模型的骨骼长度、刚体大小和动作幅度差异很大，不能把某个模型的数值直接套到另一个模型上。

### 5. 针对裙摆穿透的处理

裙摆穿透通常由“碰撞体太小、碰撞组不正确、相邻动态骨骼间距过大”中的一项或多项造成。可以按以下顺序处理：

1. 先恢复或选择 `PA_<模型名>_ALL`，确认裙摆能检测到身体和腿部碰撞体。
2. 在 Physics Asset Editor 中适当扩大腿部、臀部或身体碰撞体，但不要让碰撞体大幅穿出模型表面。
3. 在 KawaiiPhysics 节点中略微增加 `Radius`。
4. 如果相邻裙摆骨骼之间有明显空隙，可在 **Bones → Bone Subdivision** 中增加 `Bone Subdivision Count`，提高长骨段之间的碰撞检测密度；这会增加计算量。
5. 仍然穿透时，再检查该裙摆动态链是否应该使用另一个 `Gxx` 碰撞组，并确认 PMX 的不碰撞遮罩没有禁止这对碰撞。

相反，如果裙摆被身体“弹飞”，先减小 `Radius` 或碰撞体尺寸，再检查是否误选了包含过多身体部位的碰撞组。

## 不建议直接修改的内容

- 不要为了修复穿透而随意删除或重排 ABP 中的 MMD IK/约束节点。
- 不要同时用同一批碰撞体填充 Physics Asset 和 KawaiiPhysics 节点的 `Spherical Limits`、`Capsule Limits`、`Box Limits`，否则可能产生重复碰撞。
- 不要一次修改多个动态链、多个 Physics Asset 和全部物理参数；很难定位问题来源。
- 重新导入模型后应重新确认 ABP 中的 Physics Asset 是否仍然指向预期的 `_ALL` 或 `_Gxx` 资产。

KawaiiPhysics 的碰撞形状、参数、骨骼细分、曲线和外力还有更多用法，请参考[KawaiiPhysics 官方碰撞设置文档](https://pafuhana1213.github.io/KawaiiPhysics-Portal/en/docs/features/collision-setup)以及[官方参数参考](https://pafuhana1213.github.io/KawaiiPhysics-Portal/en/docs/parameters/physics)。

模型姿态和物理确认完成后，可以继续[04 M2U 材质调节](04-M2U材质调节.md)。
